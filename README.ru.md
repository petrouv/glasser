# glasser

Прошивка EXIF/XMP/MakerNote-тегов объектива для кадров, снятых на мануальную
оптику через адаптеры. После импорта одной командой переписывает всё, что
относится к объективу, на реальные данные из своей базы.

Откуда «не та» информация об объективе берётся в EXIF — варианты, не
привязанные к конкретной системе:

- **Электронный (смарт) адаптер** (например, Shoten LM-Z E для Nikon Z).
  Адаптер рапортует камере выбранный профиль (фокусное + диафрагма), и
  камера пишет его в EXIF как «родной» объектив. Адаптер при этом сам
  не знает, что за объектив реально стоит — пользователь выбирает профиль
  на нём вручную.
- **Механическое переходное кольцо** без электроники. Бывает для любого
  байонета (Nikon, Fuji, Sony, и т.д.). Камера про объектив ничего не
  знает; в EXIF попадает либо мусор/пусто, либо то, что пользователь ввёл
  в камерном меню «non-CPU lens data» / «Mount adapter» (фокусное и
  максимальная диафрагма — обычно для IBIS и экспонометра).
- **Ручная запись** в камерное меню профиля объектива на любой системе —
  даже без адаптера, если объектив на родном байонете без чипа.

Во всех случаях правильную идентификацию объектива нужно проставить
постфактум — для этого и есть `glasser`.

## Быстрый старт (macOS)

По шагам — для тех, кто редко работает в терминале. На Linux то же самое
без Homebrew, на Windows — через WSL (см. [Установка](#установка)).

Поддерживаемые камеры: Nikon Z f, Fujifilm X-T4, X-E5 и X-E3. Для другой
камеры нужна одна строка в скрипте (см. [База](#база)).

1. Открой **Терминал** (Spotlight: ⌘ Пробел, набери «Терминал»).
2. Поставь [Homebrew](https://brew.sh): скопируй команду установки с его
   страницы в Терминал и нажми Enter. Потом поставь exiftool:
   ```bash
   brew install exiftool
   ```
3. Скачай glasser: на GitHub **Code → Download ZIP**, распакуй, например,
   в «Документы». В Терминале набери `cd ` (с пробелом), перетащи
   распакованную папку из Finder в окно Терминала, нажми Enter.
4. Создай свой список объективов и открой его в TextEdit:
   ```bash
   cp lenses.example.ini lenses.ini
   open -e lenses.ini
   ```
   Замени примеры своими объективами (формат описан в начале файла и в
   разделе [База](#база)) и сохрани.
5. Установи команду `glasser` и сделай её доступной (один раз):
   ```bash
   make install
   echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zprofile
   echo 'export GLASSER_LANG=ru' >> ~/.zprofile
   ```
   Вторая строка включает русский интерфейс: у Терминала часто стоит
   английская локаль, даже если macOS по-русски. Закрой Терминал и открой
   снова.
6. **glasser перезаписывает снимки на месте, без резервных копий.** Сначала
   попробуй на копии папки. Набери `glasser ` (с пробелом), перетащи папку
   со снимками в окно, нажми Enter. Для каждой группы снимков glasser
   показывает угаданные камеру и объектив: Enter — принять, `n` — выбрать
   из списка. В конце он показывает план и ещё раз спрашивает, прежде чем
   что-то записать. `glasser --dry-run <папка>` покажет, что будет
   записано, не трогая файлы.

## Установка

Требования: bash, exiftool (`brew install exiftool`).

```bash
cp lenses.example.ini lenses.ini   # и заполнить своими объективами
make install        # симлинк в ~/.local/bin/glasser
make uninstall      # снять
make                # справка
```

`~/.local/bin` должен быть в `PATH`; macOS по умолчанию его туда не
добавляет (см. [Быстрый старт](#быстрый-старт-macos), шаг 5).

Платформы: **macOS** — проверено (bash 3.2 и 5). **Linux** — тесты
проходят на Debian 13 (bash 5.2); exiftool — из дистрибутива (`sudo apt
install libimage-exiftool-perl` в Debian/Ubuntu). **Windows** — через WSL
(Linux внутри Windows): не проверено, но это та же среда Linux; диски
Windows — в `/mnt/c/…`. Git Bash и обычный Windows (cmd, PowerShell) не
поддерживаются.

Симлинк — чтобы правки в `lenses.ini` и `load_camera_db` подхватывались
без пересборки. `lenses.ini` скрипт ищет рядом со своим настоящим файлом
(симлинк разворачивается), поэтому копировать его в `~/.local/bin` не
нужно. Другой файл базы — через `GLASSER_LENS_DB=путь`.

`lenses.ini` — личная база, в git не попадает (`.gitignore`); в
репозитории лежат шаблон `lenses.example.ini` и тестовая база
`tests/lenses.ini`.

## Язык интерфейса

По умолчанию glasser пишет по-английски. Русский включается, если локаль
(`LC_ALL`, иначе `LC_MESSAGES`, иначе `LANG`) начинается с `ru`;
`GLASSER_LANG=en` или `GLASSER_LANG=ru` задаёт язык явно и перекрывает
локаль. Цитаты экрана ниже — русский интерфейс.

Русские строки лежат в `locale/ru.sh` рядом со скриптом; его, как и
`lenses.ini`, glasser ищет рядом со своим настоящим файлом, поэтому
установка симлинком работает. Это bash-файл с тремя функциями:
`_l10n_ru` (английская строка → русская), `_plural_ru` (форма
существительного для числа) и `_help_ru` (текст `--help`). Ключи — точные
английские строки из `glasser`, вместе с `%s` / `%d`; нет перевода —
выводится английский текст. Нет файла `locale/<язык>.sh` — весь интерфейс
английский.

Новый язык — см. [CONTRIBUTING.md](CONTRIBUTING.md#translations) (на английском).

## Использование

```
glasser                       обработать текущую папку (с подпапками)
glasser PATH                  обработать указанную папку (с подпапками)
glasser --list-lenses         таблица объективов
glasser --list-cameras        таблица камер
glasser --dry-run [PATH]      показать команду, не записывать
glasser --no-confirm [PATH]   без интерактива (по угаданному)
glasser --camera ID [PATH]    принудительно эта камера
glasser --lens   ID [PATH]    принудительно этот объектив
glasser --verbose [PATH]      сериальный прогресс вместо прогресс-бара
glasser --no-art [PATH]       без заставки, спиннера и анимации
glasser --version             версия
glasser --help                справка
```

Папка сканируется **рекурсивно** — вместе со всеми подпапками.
Обрабатываются расширения `jpg`, `jpeg`, `nef`, `raf`, `tif`, `tiff`,
`dng`, `arw`, `cr2`, `cr3` (регистр не важен). Запуск в родительской
папке затронет кадры во всех вложенных.

`--camera` / `--lens` действуют на **все** группы папки (см.
«Группировка») — и в интерактиве, и в `--no-confirm`.

При записи (в карточном режиме, см. «UI в TTY и в pipe») отображается
прогресс-бар в виде одной обновляющейся строки:

```
[████████████░░░░░░░░░░░░░░░░░░░░░░░░░░░░]  30% (24/80) _DSC0042.NEF
```

С флагом `--verbose` или вне карточного режима (вывод перенаправлен в
файл/pipe, `TERM=dumb`, терминал не ответил на запрос позиции курсора)
вместо бара печатается сериальный вывод exiftool — по строке на файл:

```
======== /path/_DSC0042.NEF [24/80]
```

## Поток выполнения

Запись в файлы происходит в **два этапа**: сначала собираются решения по
всем группам (commit), потом одной командой применяется план (apply).
До применения плана **ничего не пишется**: если на финальном вопросе
передумал — можно отменить, ничего не записано. Сама запись не
транзакционна: exiftool пишет по файлу. Если на какой-то группе exiftool
вернул ошибку (заблокированный файл, нет прав, кончился диск), остальные
группы всё равно обрабатываются, в финальной сводке сбойная группа
помечена «ошибка» (часть её файлов могла записаться), код выхода — 1.
Ctrl-C во время записи останавливает прогон после текущего exiftool:
текущая группа могла записаться частично, следующие не тронуты, код
выхода — 130. Повторный запуск безопасен: уже прошитые файлы получат те же значения.

```
1. Сканирование папки (батч exiftool, читает Make/Model/Lens*/Focal*/MaxAp)
2. Группировка по сигнатуре (одна камера + один объектив = одна группа)
3. Commit-фаза, по каждой группе:
     • угадал камеру + объектив (или попросить выбрать)
     • спросил: Принять выбор?   Y принять   n исправить   s пропустить   q выйти
4. Apply-фаза:
     • сводный план + tag-preview по каждой группе
       (что именно ляжет в EXIF)
     • спросил: Применить план? [Y/n]
     • exiftool пишет в файлы группа за группой
5. Финальная сводка.
```

Промпты:

| Где | Опции | Что значит |
|---|---|---|
| Commit (на каждую группу) | `Y` / `n` / `s` / `q` | `Y` принять, `n` поправить (камера→объектив), `q` выйти, `s` пропустить группу |
| Меню камеры/объектива | номер | `Enter` оставить текущий выбор; `0` — назад к «Принять выбор?» с прежним выбором (`0) Назад`), а если угадано не всё и возвращаться некуда — пропустить группу (`0) Пропустить группу`). Выход из всего — только `q` |
| Apply (один раз) | `[Y/n]` | `Y` применить весь план, `n` отменить (ничего не записано) |

В `--no-confirm` оба интерактивных промпта пропускаются, но план с
tag-preview всё равно печатается — для прозрачности. Без терминала
(cron, CI, pipe) интерактивный режим не запускается: без `--no-confirm`
glasser сразу выходит с ошибкой «нет терминала — используй
--no-confirm», ещё до сканирования. Это касается и `--dry-run` — он тоже
спрашивает по группам.

Коды выхода:

- `0` — готово, либо отмена пользователем (`q`, `n` на «Применить
  план?»), либо все группы пропущены;
- `1` — ошибка: нет `lenses.ini` или в нём ошибка (сообщение с номером
  строки), неверные аргументы или id в `--camera`/`--lens`
  (проверяются до сканирования), в папке нет изображений (или все
  найденные пропущены — причина и число в сообщении), не угадано или
  неоднозначно в `--no-confirm`, нет терминала, Ctrl-D (EOF) в промпте
  или в меню без угаданного значения (в меню с угаданным Ctrl-D = Enter),
  ошибка exiftool хотя бы в одной группе;
- `130` — прервано Ctrl-C: до записи (промпты, `--dry-run`) ничего не
  записано; во время записи текущая группа могла записаться частично,
  следующие не тронуты.

### UI в TTY и в pipe

Карточный режим включается, только если выполнены все три условия:

1. **stdout** — терминал (`-t 1`); stderr и stdin не проверяются;
2. `TERM` задан и не `dumb`;
3. терминал ответил на запрос позиции курсора (CSI 6n) — glasser
   спрашивает один раз при старте, ждёт до 1 с.

Иначе вывод линейный. Промпты и меню пишутся в **stderr**, ответы
читаются из `/dev/tty`. Поэтому `glasser >log` даёт линейный протокол с
промптами на экране, а `glasser 2>log` оставляет карточки, но уводит
промпты и меню в файл. Для интерактива нужен открываемый `/dev/tty` (см.
выше); без него — только `--no-confirm`.

- **Карточный режим**: экран очищается (scroll-back сохраняется),
  наверху баннер `◉ glasser · <папка> · N файлов`, каждая группа —
  «карточка» с in-place перерисовкой. Когда переходишь от prompt'а к
  меню коррекции и обратно — содержимое перерисовывается на том же
  месте, шапка карточки служит якорем. По `Y`/`s` (и в `--no-confirm`
  после успешного угадывания) карточка сворачивается в одну
  строку-сводку.
- **Линейный режим** (pipe, перенаправление stdout в файл, cron,
  `TERM=dumb`, терминал без ответа на CSI 6n): без перерисовок, без
  очистки экрана, без стирания. Карточки превращаются в обычный
  линейный протокол; всё, что было показано, остаётся, строка-сводка
  группы печатается ниже.

#### Заставка и анимация

В карточном режиме на экране от 30×66 вместо строки-баннера наверху —
заставка: объектив со шкалой дистанций, рифлёным кольцом фокуса и
кольцом диафрагмы f/1.2–16, справа подпись (название, папка и число
файлов / групп). Цифры диафрагмы приглушённых цветов — как на старых
объективах (читаются и на светлом, и на тёмном фоне). На экране
меньше — прежняя строка `◉  glasser  ·  <папка>  ·  N файлов`.

Карточка группы тоже оформлена: всё с отступом в 2 колонки, шапка
`◉ Группа 2 из 4 · 3 файла`, тонкая линейка, бледная строка EXIF с переносом по полям, сводка с галочками
`✓ угадано` (не угаданное — янтарным `?`), поколение и серийник объектива
отдельной строкой, клавиши `Y n s q` в одну строку под вопросом.

Пока exiftool стартует, крутится диафрагма-спиннер `· ○ ◎ ◉ ◎ ○`
(«Сканирую…»), затем тот же кадр стоит перед строкой прогресса
сканирования. В конце, перед `✓ Готово.`, — «щелчок затвора»
(диафрагма закрывается и открывается, только если stdout — терминал).

`--no-art` или `GLASSER_NO_ART=1` выключают всё это (строка-баннер,
прежняя карточка с `EXIF:` и `[Y] принять`, без спиннера и щелчка). Вне
карточного режима (pipe, файл, `TERM=dumb`) вывод тоже прежний. `NO_COLOR` (любое непустое значение,
[no-color.org](https://no-color.org)) оставляет рисунок, но без цвета.

## Группировка

При запуске папка **всегда** сначала сканируется одной батч-командой
`exiftool`, читаются `Make + Model + LensModel + FocalLength +
MaxApertureValue`, файлы группируются по этой сигнатуре. Потом скрипт
проходит по группам по очереди, для каждой — обычный поток (угадал
→ подтверждение / коррекция → запись только в файлы этой группы).

Зачем: защита от микса. Если в папке оказались кадры с двух камер или
с разными объективами, они окажутся в разных группах и каждая прошьётся
своими тегами. Если в папке один кадр от чужой камеры случайно — он
будет отдельной группой из 1 файла, можно нажать `s` (skip) и не
трогать его.

Промпт подтверждения перечисляет клавиши после вопроса:

```
Принять выбор?   Y принять   n исправить   s пропустить   q выйти
```

Без карточек (pipe, `TERM=dumb`) или с `--no-art` клавиши идут
отдельными строками: `[Y] принять`, `[n] исправить`,
`[s] пропустить группу`, `[q] выйти`. `Y` (или Enter) пишет группу, `n` — коррекция,
`s` — пропустить группу и перейти к следующей, `q` — выход.

`--camera ID` / `--lens ID` подменяют угадывание во **всех** группах
сразу (в интерактиве выбор можно поправить через `n`). В `--no-confirm`
режиме требуется успешное угадывание (или эти overrides) для **каждой**
группы; иначе ошибка с указанием, какая именно не угадалась, и ни один
файл не записывается.

## База

Объективы — в файле `lenses.ini` рядом со скриптом, камеры — хардкодом
в функции `load_camera_db` в самом скрипте.

**Объектив** — секция в `lenses.ini`:

```ini
[jupiter-9]
make        = Jupiter
model       = 9 85mm f/2
display     = Юпитер-9 85мм f/2
focal       = 85
max         = 2
min         = 16
serial      =
lens_string = 85mm f/2
generation  = белый
```

- `[id]` — то, что передаётся в `--lens`; уникальный, без пробелов.
- `model` — без бренда, `display` — полное имя с брендом.
- `max`, `min` — светосила и минимальная диафрагма (f-числа).
- `lens_string` — короткая форма для `Nikon:Lens`, например `58mm f/1.9`.
- `generation` — короткий маркер ревизии/версии для UX-различения нескольких
  копий одной модели в меню (`M-4`, `II`, `D`, `белый`, …). В EXIF не
  пишется. Если у тебя одна копия — оставь пустым.
- `serial` и `generation` можно не писать вовсе, остальные ключи
  обязательны. Значение — всё после первого `=`, пробелы по краям
  обрезаются; комментарии — только целой строкой с `#`.
- Ошибки в файле (неизвестный или повторный ключ, пропущенный
  обязательный, повторный id или пробел в нём, строка не по формату) останавливают
  скрипт до сканирования, с указанием `lenses.ini:N`.

**Камера:**

```
add_camera "ID" "make_regex" "model_regex" "Display" \
           crop_factor "MakerNoteGroup" has_nikon_lens
```

`model_regex` — обязательно `^...$`, иначе `Z f` сматчится с `Z fc`.
`MakerNoteGroup` ∈ {`Nikon`, `FujiFilm`, `""`} (другое значение — ошибка
при загрузке базы). `has_nikon_lens` (`true`/`false`)
— писать ли отдельный тег `Nikon:Lens`.

## Что пишется

| Тег | Зачем |
|---|---|
| `LensMake`, `LensModel`, `LensSerialNumber` | Стандарт, читают все |
| `LensInfo` | `Focal Focal MaxAp MaxAp` (см. ниже) |
| `MaxApertureValue`, `FocalLength`, `FocalLengthIn35mmFormat` | Свойства объектива |
| `XMP-aux:Lens`, `XMP-aux:LensSerialNumber` | Для Adobe |
| `XMP-exifEX:LensMake`, `LensModel`, `LensSerialNumber`, `LensInfo` | Современный аналог; `LensInfo` — имя exiftool для XMP-свойства `exifEX:LensSpecification` (см. «Группа `-EXIF:` для LensInfo обязательна») |
| `Nikon:MinFocalLength`, `Nikon:MaxFocalLength`, `Nikon:MaxApertureAt{Min,Max}Focal`, `Nikon:Lens` | Для NX Studio |
| `FujiFilm:MinFocalLength`, `FujiFilm:MaxFocalLength`, `FujiFilm:MaxApertureAt{Min,Max}Focal` | Для X RAW Studio |

## Что **не** пишется

- `FNumber`, `ApertureValue` — per-shot, не lens-уровень.
- `LensType`, `LensIDNumber`, `AF Aperture`, `Effective Max Aperture`,
  `Lens Mount Type` — рантайм-флаги электронного адаптера, в постобработке
  не читаются (на механических переходниках и при ручном вводе их просто нет).
- `Composite:LensID`, `XMP-aux:LensID` — вычисляемые или несуществующие
  в стандарте; запись бесполезна или ломает ValueConvInv.
  (`exifEX:LensSpecification` пишется — через имя `XMP-exifEX:LensInfo`;
  имя `XMP-exifEX:LensSpecification` exiftool не принимает.)
- `XMP-aux:SerialNumber` — это серийник **корпуса**. Старые версии glasser
  ошибочно писали туда серийник объектива; при перепрошивке такой тег
  стирается, но только если он совпадает со старым `ExifIFD:LensSerialNumber`
  и не совпадает с `ExifIFD:SerialNumber`. Чужое значение не трогается.

Серийники объектива пишутся всегда: если в базе серийника нет, теги
`LensSerialNumber` стираются, чтобы при перепрошивке не остался серийник
предыдущего объектива.

## Подводные камни

### LensInfo по стандарту — это не «открытая–закрытая»

`Exif 2.32 LensSpecification` — 4 рациональных числа:

1. min focal
2. max focal
3. **min F-number** (= макс. открытая) на min focal
4. **min F-number** (= макс. открытая) на max focal

Третий и четвёртый — оба про **открытую** диафрагму, просто на двух краях
зума. Для прайма оба равны: `57 57 1.2 1.2`. Закрытая диафрагма в LensInfo
**не пишется** — её там нет по спеке.

exiftool при чтении печатает `57mm f/1.2`, если значения 3 и 4 равны, и
`57mm f/1.2-X`, если разные. Бытовая интуиция «MinAperture = открытая,
MaxAperture = закрытая» — путь к нестандартным значениям и странным
строкам типа `57mm f/1.2-16` в каталогизаторах.

В базе скрипта поле `min_aperture` всё равно хранится, но сейчас нигде не
выводится и не пишется — задел на будущее (печать в `--list-lenses`,
возможная запись в MakerNote).

### Nikon квантует фокусное в MakerNote

Запишешь `Nikon:MinFocalLength=58` — на чтении получишь `58.2 mm`, для 57 —
`56.6 mm`. Это не баг: формат Nikon хранит фокусное одним байтом по
нелинейной шкале, не все целые миллиметры представимы точно. «Удобные»
точки (24, 35, 50, 85, 105) попадают почти точно.

Стандартный `EXIF:FocalLength` (rational) остаётся ровным `58.0`. RAW-
конвертеры читают именно его, не Nikon MakerNote. Влияния на работу
конвертеров нет.

### Composite:LensID — производитель-специфичен

Это **вычисляемое** поле, его физически нет в файле; exiftool синтезирует
на чтении.

- **Nikon:** хеш из 8 байт MakerNote (`Nikon:LensIDNumber`, `LensType`,
  `LensFStops`, `Min/MaxFocalLength`, `MaxApertureAt{Min,Max}Focal`,
  `MCUVersion`) ищется в захардкоженной таблице ~500 Nikkor-ов. Для
  мануала (через электронный адаптер, механическое кольцо или ручной ввод)
  хеша в таблице нет → **`Unknown (XX YY ...)`**.
  Это правильно: чтобы этого избежать, пришлось бы подделать байты под
  какой-то реальный Nikkor, и NX Studio попыталась бы применить чужой
  профиль коррекции. Идентификация мануала живёт в `LensMake + LensModel`,
  которые мы пишем явно.
- **Fuji:** нет таблицы хешей. exiftool склеивает Composite:LensID из
  текстовых `LensMake + LensModel` (с фолбэком на XMP-aux/exifEX). Поэтому
  для Fuji Composite:LensID показывает читаемое имя сразу после прошивки.

### Группа `-EXIF:` для LensInfo обязательна

Скрипт пишет `-EXIF:LensInfo=...` (с явной группой), а не просто
`-LensInfo=...`. Без группы exiftool интерпретирует тег как «без приписки»
и **дублирует** запись во все группы, где этот тег определён — включая
автоматическую запись в `XMP-exifEX:LensSpecification`. Тогда наша явная
`-XMP-exifEX:LensInfo=...` рядом добавляется поверх → `rdf:Seq` получает
8 элементов вместо 4, и это не идемпотентно.

С явной группой `-EXIF:` пишет только в EXIF, `-XMP-exifEX:` — только в
XMP, оба в одной команде, ровно 4 элемента в Seq. Это классическая ошибка
из exiftool [Common Mistakes](https://exiftool.org/mistakes.html) — забыть
указать группу для тега, который существует сразу в нескольких namespaces.

### `MaxApertureValue` vs `FNumber`

- `MaxApertureValue` — свойство объектива, макс. открытая. **Перезаписываем.**
- `FNumber`, `ApertureValue` — свойства конкретного кадра. Камера для
  мануала ставит мусор. **Не трогаем** — это per-shot, не lens-уровень.

### Что определяется при автоопределении

Данные берутся из первого файла группы.

1. Если `LensModel` в EXIF содержит модель из базы, а `LensMake` пуст или
   тоже совпадает (повторная прошивка) — берём оттуда.
2. Иначе — матч по `EXIF:FocalLength` (±0.5 мм — запас на округлённое или
   неточное фокусное от адаптера, чипа или ручного ввода; Nikon-квант
   MakerNote тут ни при чём, `EXIF:FocalLength` ровный).
3. При нескольких кандидатах — тай-брейк по `MaxApertureValue` (±0.05).
   Если `MaxApertureValue` пуст, берётся f-число из `LensInfo` (`58mm
   f/1.9` → 1.9). Если диафрагмы нет и там — тай-брейка нет, объектив не
   угадан.

Если после шага 1 (`LensModel` без `LensMake` совпал с несколькими
записями) или шага 3 (несколько кандидатов с той же диафрагмой, например
50/1.2 — Canon FD 50mm f/1.2 и FD 50mm f/1.2 L) остаётся больше одного объектива, это
**не угадано**: в `--no-confirm` — ошибка со списком кандидатов
(«неоднозначен: canon-fd-50-12, canon-fd-50-12l — нужен --lens ID»), в
интерактиве сразу открывается меню. Первая подходящая строка базы
молча не берётся. Единственный кандидат по фокусному берётся без
проверки диафрагмы (см. ниже).

`MaxApertureValue` из EXIF доверять как первичному критерию **нельзя**:
там либо значение профиля электронного адаптера, либо `1.0` / `undef`, либо
то, что пользователь ввёл в камерном меню — реального соответствия объективу
нет.
